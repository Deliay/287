# UI/UX 设计文档（design）规范

本目录存放 UI/UX 设计文档，是开发前置流程的**第二阶段**产出物。

## 何时编写

对应主题的产品需求文档（`../requirement/`）建立并确认后，才开始本阶段。

## 文档必须包含的内容

1. **对应需求**：链接或引用 `../requirement/` 中的需求文档。
2. **设计稿**：页面/组件的视觉稿或原型（图片文件放在本目录或 `resources/`，文档内引用相对路径）。
3. **交互说明**：页面流转、状态变化（加载、空态、错误态）、用户操作的反馈。
4. **覆盖性自查**：逐项确认需求文档中的用户场景均有对应设计。
5. **Review 记录**：评审人、评审日期、结论（通过 / 不通过及原因）。

## 完成条件（DoD）

- 需求中的全部用户场景均有设计覆盖。
- **需求 + 设计均通过 Review 后**，才能进入技术方案阶段（`../../engineering/proposal/`）。

## 注意事项

- 设计稿资源文件统一使用项目已有的图片格式（优先 webp/avif，参考 `resources/`）。
- 设计变更时同步更新本文档，并检查是否需要回写需求文档。
- 文档命名遵循 `../AGENTS.md` 中的通用约定，主题名与需求文档保持一致。
