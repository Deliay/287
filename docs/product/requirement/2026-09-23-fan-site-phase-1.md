# 287 粉丝站 · 第一期（首页与成员展示）产品需求文档

- 版本：v1.0
- 创建日期：2026-09-23
- 状态：待 Review

## 1. 背景与目标

VirtuaReal 二十八期（"287"期）四位成员（小松绿 Viridis、四时小路 Komichi、羽啾 Chu2u、枝堇 Sumire）已于 2026 年 8 月出道，目前缺少一个集中展示四位成员形象与资料的粉丝站点。

本期目标：搭建粉丝站的基础工程（Next.js + Mantine），并交付**首页**——以四位成员立绘为核心的全屏视觉展示页，建立站点的视觉基调（调色盘）与导航框架，为后续期次（资讯、二创、直播日历等）打基础。

## 2. 用户场景

| # | 场景 | 描述 |
|---|------|------|
| S1 | PC 端访客打开首页 | 首屏并排看到四位成员的立绘（上半身），直观感受 287 期的整体形象 |
| S2 | PC 端访客对某位成员产生兴趣 | 鼠标悬停在该成员立绘上，该成员高亮、其余变灰；点击跳转其 B 站主页 |
| S3 | PC 端访客向下滚动 | 滚动带有阻尼感，依次进入四位成员的单独介绍区，左侧立绘半身、右侧文字介绍 |
| S4 | 移动端访客打开首页 | 四位成员立绘纵向等分占满首屏，顺序与 PC 一致 |
| S5 | 移动端访客向下滚动 | 依次进入四位成员的介绍区 |
| S6 | 任意端使用导航栏 | 导航栏固定在顶部，PC 端链接右对齐；移动端折叠为菜单按钮，点击展开。当前仅有「首页」一项 |

## 3. 功能需求

### FR-1 调色体系

- As a 访客，I want 站点有统一且与成员对应的色彩体系，so that 浏览时能直观区分成员并感受 287 期的整体氛围。
- 选定一套「287」团体调色盘，作为站点全局基调（背景、导航、文字等）。
- 以每位成员的代表色为基础，各选定一套成员调色盘，用于该成员相关的强调色（介绍区标题、hover 态、链接等）。
- 成员代表色（取自官方设定，见 `resources/`）：
  - 小松绿 Viridis：`#8eb056`
  - 四时小路 Komichi：`#FF2231`
  - 羽啾 Chu2u：`#D4DA7B`
  - 枝堇 Sumire：`#B4A6BF`

### FR-2 导航栏

- As a 访客，I want 通过顶部导航栏在站点内移动，so that 后续期次的页面可以统一接入。
- 导航栏固定于页面顶部。
- PC 端：导航项**右对齐**排列；当前仅有一项「首页」，点击回到首页顶部。
- 移动端：导航项折叠为菜单按钮（如汉堡按钮），点击后展开菜单展示导航项。
- 导航栏样式使用「287」团体调色盘，不遮挡首屏立绘的关键视觉区域。

### FR-3 首页首屏（成员立绘墙）

- As a 访客，I want 首屏看到四位成员的立绘并列展示，so that 快速认识 287 期全员。
- 展示顺序严格按照官方海报「**绿黑白紫**」：小松绿 Viridis → 四时小路 Komichi → 羽啾 Chu2u → 枝堇 Sumire。
- PC 端：
  - 四列并排，每列展示一位成员立绘的**上半身**部分，四列**宽度占满屏幕**（各 25%），整体**竖向占满首屏**。
  - 鼠标悬停某一列时：该列高亮（正常色彩，可有放大/提亮反馈），其余三列**变灰**；移出后恢复。
  - 点击某一列：新标签页打开该成员的 **B 站主页**。
- 移动端：
  - 四行纵向排列，每行**横向占满屏幕**，四位成员**高度平分首屏**（各 25%），顺序同为「绿黑白紫」。
  - 移动端无 hover 态；点击某一行：新标签页打开该成员的 B 站主页。
- 立绘素材使用 `resources/` 下对应的 `.avif` 图片，通过裁切/定位展示上半身。

### FR-4 阻尼滚动与成员介绍区

- As a 访客，I want 向下滚动时有阻尼感并依次看到成员介绍，so that 浏览体验流畅、有仪式感。
- 首页向下滚动带有**阻尼感**（非浏览器生硬的即时滚动）。
- 首屏之后依次为四位成员的**单独介绍区**，顺序与首屏一致（绿黑白紫）。
- PC 端介绍区布局：左侧为成员**立绘半身**，右侧为文字介绍。
- 移动端介绍区布局：适配窄屏的纵向布局（立绘与介绍上下排布，具体见设计文档）。
- 介绍内容包含：成员名称、身份/称号、简介、代表色视觉强调、B 站主页入口。
- 介绍文案取自 `resources/` 下各成员资料（见「数据依赖」）。

### FR-5 工程基础

- As a 开发者，I want 项目基于 Next.js + Mantine 初始化完成，so that 后续期次可以在统一技术栈上迭代。
- 在当前仓库根目录初始化 Next.js（App Router + TypeScript）项目，集成 Mantine 组件库。
- 脚手架通过 `pnpm build` 与 `pnpm lint`。

## 5. 非功能需求

- **响应式**：以 Mantine 断点为基准，移动端断点为 `< 48em`（768px）；需覆盖常见手机与桌面宽度。
- **性能**：立绘图片使用 avif 格式并经 `next/image` 优化；首屏图片合理设置 `priority`，避免首屏长时间空白。
- **可访问性**：立绘均有 `alt` 文本；hover 变灰效果不应是唯一信息通道（成员名称始终可读）；色彩对比度满足 WCAG AA。
- **兼容性**：支持主流现代浏览器（Chrome / Edge / Safari / Firefox 最近两个大版本）及 iOS Safari、Android Chrome。

## 6. 范围边界（本期不做）

- 导航栏除「首页」外的任何页面（资讯、二创、日历等）。
- 成员详情**独立路由页**（本期介绍区仅为首页内的滚动区块）。
- 直播状态、动态抓取等任何后端/数据接口能力。
- 多语言、深色/浅色模式切换（本期仅按设计文档的单一主题落地）。
- 立绘之外的图片素材制作（如官方海报授权素材）。
