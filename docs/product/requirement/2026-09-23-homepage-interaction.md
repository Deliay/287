# 287 粉丝站 · 首页交互优化 产品需求文档

- 版本：v1.0
- 创建日期：2026-09-23
- 状态：待 Review

## 1. 背景与目标

第一期（见 `2026-09-23-fan-site-phase-1.md`）已交付首页立绘墙与成员介绍区，但存在两个体验断点：

1. 首屏点击成员直接跳出站点到 B 站空间，访客尚未了解成员即流失；
2. 站点无法传达「成员是否正在直播」这一粉丝最关心的实时信息；
3. 首页滚动为连续阻尼滚动，成员介绍区之间没有明确的「逐屏浏览」节奏。

本期目标：优化首页交互闭环——首屏点击改为站内跳转到成员介绍区、首屏与介绍区均展示实时直播状态、滚动改为按介绍区逐屏吸附，提升站内留存与直播导流效率。

## 2. 用户场景

| # | 场景 | 描述 |
|---|------|------|
| S1 | 访客对首屏某位成员产生兴趣 | 点击该成员立绘，页面平滑滚动到该成员的介绍区（站内，不再跳出到 B 站） |
| S2 | 访客想知道谁正在直播 | 首屏每位成员名字上方直接看到直播状态：开播中显示直播标题，未开播显示「未开播」 |
| S3 | 访客浏览到成员介绍区 | 介绍区同样展示该成员的直播状态，信息与首屏一致 |
| S4 | 访客点击直播状态 | 跳转该成员的直播相关入口（开播时引导观看；具体目标见 §7 待确认项） |
| S5 | 访客向下滚动 | 滚动直接定位到下一个成员介绍区的中心位置，逐屏浏览，而非停在任意中间位置 |

## 3. 功能需求

### FR-1 首屏点击跳转改为站内锚点

- As a 访客，I want 点击首屏成员立绘后在站内看到该成员的介绍，so that 我可以先了解成员再决定是否关注。
- 首屏立绘墙中点击某成员，**不再**新标签页打开 B 站主页，改为平滑滚动到首页内该成员的介绍区（member section）。
- 介绍区中原有的「前往 B 站主页」入口保持不变，B 站跳转收敛到介绍区内。

### FR-2 首屏直播状态显示

- As a 访客，I want 在首屏直接看到每位成员是否开播，so that 不错过正在进行的直播。
- 首屏立绘墙中，每位成员**名字上方**展示直播状态徽章：
  - **开播中**：显示直播标题（取自状态接口）。
  - **未开播**：仅显示「未开播」。
- 状态数据来自实时接口（见 §7 数据依赖），每位成员对应一个接口地址。
- 点击直播状态徽章：跳转该成员直播入口（开播时引导至直播间，具体跳转目标见 §7 待确认项 T1）。
- 接口请求失败时不阻断页面：状态降级显示为「未开播」样式或隐藏徽章（以设计文档为准），首屏其余内容不受影响。

### FR-3 介绍区直播状态显示

- As a 访客，I want 在成员介绍区也看到直播状态，so that 浏览介绍时能直接前往观看。
- 每个成员介绍区展示该成员的直播状态，显示逻辑与首屏完全一致（开播显示标题 / 未开播显示「未开播」）。
- 同一成员在首屏与介绍区的状态必须一致（同一数据源，不重复请求）。

### FR-4 逐屏吸附滚动

- As a 访客，I want 滚动时页面逐屏停留在成员介绍区，so that 浏览节奏清晰、不错过内容。
- 从首屏向下滚动时，页面直接滚动定位到（第一个）成员介绍区的**中心**位置。
- 处于某个介绍区时继续向下滚动，跳转到**下一个**介绍区；向上滚动则回到上一个介绍区/首屏。
- 滚动吸附与既有的阻尼滚动手感（lenis）协调，不产生冲突或抖动。
- 移动端同样生效，但不得以牺牲触屏滚动的跟手性为代价。

## 4. 验收标准

| # | 对应需求 | 验收条件 |
|---|----------|----------|
| AC-1 | FR-1 | 点击首屏任一成员立绘，页面滚动到对应成员介绍区，无新标签页打开；介绍区「前往 B 站主页」链接仍可正常跳转 |
| AC-2 | FR-2 | 首屏四位成员名字上方均出现直播状态徽章；mock 接口返回开播时显示接口给的直播标题，返回未开播时显示「未开播」 |
| AC-3 | FR-2 | 点击直播状态徽章的跳转行为符合 §7-T1 确认后的结论 |
| AC-4 | FR-2 | mock 接口请求失败/超时，页面正常渲染，无未捕获异常，徽章按设计降级 |
| AC-5 | FR-3 | 四个介绍区均展示直播状态；同一成员首屏与介绍区状态一致；每位成员的接口在整个页面生命周期内不被重复并发请求 |
| AC-6 | FR-4 | PC 端从首屏向下滚动，页面停留在第一个介绍区中心；继续下滚依次进入后续介绍区；上滚可回到首屏 |
| AC-7 | FR-4 | 移动端滚动吸附生效且触屏滚动无卡顿、无滚动劫持感 |
| AC-8 | 全部 | `pnpm test`、`pnpm lint`、`pnpm build` 全绿；既有首页测试（hover、顺序、导航）不因本次改动失效（FR-1 涉及的跳转断言同步更新） |

## 5. 非功能需求

- **性能**：直播状态请求在客户端按需发出，不阻塞首屏渲染；轮询/刷新策略（如需要）间隔不短于 60s，避免对接口造成压力。
- **兼容性**：与第一期一致（主流现代浏览器 + iOS Safari / Android Chrome）；状态接口不可用时整站功能不受影响。
- **可访问性**：直播状态徽章为可聚焦元素并有可读文本（不依赖纯图标/颜色传达状态）。
- **隐私/安全**：仅请求需求中列出的四个状态接口，不引入第三方脚本。

## 6. 范围边界（本期不做）

- 成员**独立路由**详情页（「详情页」在本期中仍指首页内的成员介绍区）。
- 直播间内嵌播放、弹幕、在线人数等标题之外的直播信息。
- 直播状态的实时推送（WebSocket/SSE）；本期仅 HTTP 轮询或一次性拉取。
- 直播日历、开播通知、历史直播记录。
- 导航栏新增项及首页之外的任何页面改动。
