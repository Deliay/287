# 287 粉丝站 · 录播模块产品需求文档

- 版本：v1.0
- 创建日期：2026-09-23
- 状态：待 Review

## 1. 背景与目标

287 期四位成员（小松绿 Viridis、四时小路 Komichi、羽啾 Chu2u、枝堇 Sumire）的直播内容由录播服务（`recordings.vtuber.fffdan.com`）自动录制，弹幕/礼物等直播事件由 `api.sumire.live` 归集。参考站点 [Deliay/sumire](https://github.com/Deliay/sumire) 已实现录播浏览与回放，但存在明显体验短板：

- 听直播为**全局单例**，同时只能听 1 路，新播放会顶掉旧播放；
- 听直播绑定在页面组件上，**离开页面即断流**，回放只能以新标签页打开来回避断流；
- 录播列表按直播间分组折叠、逐组展开，信息层级深，四位成员的状态与录播没有一个统一的首屏视图。

本期目标：为 287 粉丝站增加「录播」模块，交付四个核心内容——**4 个主播当前直播状态列表、历史录播列表（后加载）、历史录播播放页（含 seek / 弹幕 / 播放控件）、悬浮播放组件**，并针对上述短板做出改进：

- 听直播从「同时 1 路」扩展为「**同时最多 4 路**」（每位成员一路）；
- 听直播**跨页面持续播放**，通过全局悬浮播放组件管理；
- 回放页为**站内路由**，不再依赖新标签页。

## 2. 用户场景

| # | 场景 | 描述 |
|---|------|------|
| S1 | 访客打开「录播」页 | 首屏看到四位成员的当前直播状态卡片（2×2 网格 / 移动端纵向），一眼知道谁在播、播什么 |
| S2 | 访客想听某位成员的直播 | 点击该成员卡片上的「听直播」，开始播放直播音频；再点击其他成员的「听直播」，多路同时播放，互不影响 |
| S3 | 访客边听直播边逛站 | 正在收听的直播不中断；页面底部出现悬浮播放组件，显示当前在听的成员，可随时停止某一路或全部停止 |
| S4 | 访客翻看历史录播 | 在状态列表下方浏览历史录播；录播数据在滚动到对应区域（或展开成员分组）时才加载，首屏不白等 |
| S5 | 访客补看某场录播 | 点击某个录播文件进入播放页，可拖动进度条 seek、开关/浏览弹幕、调节音量、全屏 |
| S6 | 移动端访客 | 全部功能在窄屏可用：状态卡片纵向排列、悬浮组件适配底部安全区、播放页控件可触达 |

## 3. 功能需求

### FR-1 导航入口

- As a 访客，I want 导航栏有「录播」入口，so that 能从任意页面进入录播模块。
- 导航栏新增「录播」项，指向 `/recordings`；PC 端右对齐排列、移动端折叠菜单内展示，样式与现有「首页」项一致。

### FR-2 直播状态列表（4 个主播当前直播状态）

- As a 访客，I want 看到四位成员当前的直播/录制状态，so that 决定听谁的直播或补谁的录播。
- 数据来源：`GET https://recordings.vtuber.fffdan.com/api/b/live/recording-status`，返回 `{items: [{mid, roomId, state: "recording"|"not_live", sessionTitle, files, updatedAt, streamer: {name}}]}`（已实测）。
- 以**成员卡片**形式展示四位成员，卡片包含：成员名、状态徽标（「直播中」/「未开播」）、当前直播标题（`sessionTitle`，未开播时不显示）、状态更新时间。
- 卡片顺序与首页一致（绿黑白紫：Viridis → Komichi → Chu2u → Sumire）；卡片视觉使用各成员调色盘作为强调色。
- 成员与房间通过 `mid`（B 站 UID，见第一期需求文档）与 `src/data/members.ts` 关联；接口未返回的成员按「未开播」兜底展示。
- 自动刷新：每 30 秒轮询一次；页面不可见（`document.hidden`）时暂停轮询，恢复可见时立即刷新。
- 布局：PC 端 2×2 网格，移动端纵向单列，位于录播页首屏。

### FR-3 多路听直播（最多 4 路同时）

- As a 访客，I want 同时收听多位成员的直播音频，so that 不错过任何一位的开播内容。
- 音频流地址：`GET https://recordings.vtuber.fffdan.com/api/b/live/{roomId}/live-stream/audio`（FLV 实时流）。
- 「听直播」按钮仅在该成员 `state === "recording"` 时可用；点击开始收听，按钮变为「停止收听」态。
- **最多同时 4 路**（每位成员至多一路）；各路独立启停、互不打断——这是对参考实现全局单例互斥的核心改进。
- 每一路可独立调节音量（悬浮组件内提供音量控制，详见 FR-6）。
- 某一路播放失败（流断开、网络错误）时，仅该路标记为失败态并提供重试入口，不影响其他路。

### FR-4 历史录播列表（后加载）

- As a 访客，I want 浏览四位成员的历史录播，so that 找到想补的场次。
- 数据来源：`GET https://recordings.vtuber.fffdan.com/api/b/live/{roomId}/recordings`，返回 `{files: [{name, size, createdAt, info: {recordingId, title, mid, startedAt, endedAt}}]}`（已实测）。
- 位于直播状态列表下方，按成员分组展示；每个文件项展示：直播标题（`info.title`，缺失时回退文件名）、录制时间（`info.startedAt`）、时长（`endedAt - startedAt`）、文件大小。
- **后加载**：进入录播页时**不**请求任何房间的录播列表；某成员的录播列表在其分组进入视口（或用户展开该分组）时才请求，加载中显示骨架/加载态，失败可重试。
- 同组成员的录播按 `info.startedAt` 倒序排列；单组数量较多时提供分页（每页 20 条）。
- 点击文件项进入站内回放页（FR-5）。

### FR-5 历史录播播放页（seek + 弹幕 + 播放控件）

- As a 访客，I want 在站内播放历史录播并看到当时的弹幕，so that 获得接近直播当时的观看体验。
- 路由：`/recordings/replay?roomId={roomId}&file={文件名}`，站内跳转（**不新开标签页**）。
- 视频流地址：`GET https://recordings.vtuber.fffdan.com/api/b/live/{roomId}/recordings/{文件名}`（FLV）。
- **播放控件**：播放/暂停、进度条（显示已缓冲区间）、音量、倍速（0.5×–2×）、全屏；控件在移动端可触达。
- **seek**：拖动进度条可跳转到未缓冲区域并继续播放；seek 中显示加载态，失败时给出明确错误提示。
- **弹幕**：
  - 数据来源：`GET https://api.sumire.live/api/live-events/replay?roomId={roomId}&start={ISO}&end={ISO}&page={n}&pageSize={m}`，返回 `{total, page, pageSize, items: [LiveEvent]}`（已实测；单次查询区间上限 12 小时，单页上限 100 条）。
  - 弹幕类型至少支持 `danmaku`（含表情弹幕 `emote`）；`super_chat` / `gift` / `guard_buy` 在事件列表中展示。
  - 视频浮层弹幕：从右向左横穿，随播放进度与视频时间轴对齐；播放头跳变 **|Δt| > 2 秒** 判定为 seek，浮层弹幕清空并按新时间点重建（2026-09-24 勘误补注阈值口径，与实现 `SEEK_JUMP_THRESHOLD_SECONDS = 2` 一致）。
  - 事件列表：按时间顺序展示**已加载窗口（当前 ± 相邻 10 分钟）内**的事件、逐窗增量加载（2026-09-24 勘误：原「全部事件」与 §5 性能条及技术方案 §5-4 的窗口化渲染取舍矛盾，长录播不全量渲染），随播放进度自动跟随高亮，点击事件可跳转到对应时间点。
  - 时间轴对齐基准：文件 `info.startedAt`（**不是** `createdAt`，分段录播的 `createdAt` 是落盘时刻）；多分段的场次按同 `recordingId` 的兄弟文件推导各分段起止。
  - 加载策略：按时间窗口（10 分钟）增量加载，播放接近窗口末尾时预取下一窗口。
- 页面顶部展示录播标题、成员名与录制时间，并提供返回录播列表的入口。

### FR-6 悬浮播放组件（跨页面持续收听）

- As a 访客，I want 切换到站内其他页面时直播音频继续播放，so that 可以边听边逛。
- 当存在至少一路进行中的「听直播」时，页面底部显示悬浮播放组件；离开 `/recordings` 页面（如回到首页）音频**不中断**。
- 组件内容：每一路显示成员名（或头像色块）+ 状态（播放中/加载中/失败）、单路音量与停止按钮；提供「全部停止」。
- 组件可收起为迷你条（仅显示在听路数），可再展开；点击成员名可跳回 `/recordings`。
- 全部路数停止后组件自动消失。
- 移动端：悬浮组件不遮挡导航菜单与主要内容，适配底部安全区。
- 悬浮组件仅承载「听直播」；录播回放（FR-5）离开播放页即停止，不进悬浮组件。

## 5. 非功能需求

- **响应式**：沿用 Mantine 断点（移动端 `< 48em`）；状态卡片 PC 2×2 / 移动单列；播放页与悬浮组件均适配移动端。
- **性能**：录播列表与弹幕均为按需加载；事件列表长列表需避免全量渲染卡顿；首屏仅请求 recording-status 一个接口。
- **兼容性**：FLV 播放依赖 MSE，覆盖 Chrome / Edge / Safari / Firefox 最近两个大版本；iOS Safari 等 MSE 不可用环境给出「无法播放，请更换浏览器」的明确降级提示（录播文件本身可下载这一点本期不开放）。
- **可访问性**：播放控件可键盘操作；状态徽标不以颜色为唯一信息通道。
- **稳定性**：直播状态轮询在页面隐藏时暂停；所有外部接口失败均有兜底 UI，不白屏。

## 6. 范围边界（本期不做）

- 录播文件下载入口。
- 弹幕发送、登录、评论等任何写操作。
- 直播日历、直播预约、开播提醒。
- 录播搜索与按标签筛选。
- 悬浮组件承载录播回放视频（仅承载听直播音频）。
- 服务端代理/转码（站点为纯静态导出，所有接口前端直连）。
