# 287 粉丝站 · 录播优化一期产品需求文档

- 版本：v1.0
- 创建日期：2026-09-25
- 状态：待 Review
- 上游：[录播模块 PRD](./2026-09-23-recordings-module.md)（已上线，本期为其体验优化迭代）

## 1. 背景与目标

录播模块（状态列表、历史录播、回放页、悬浮听直播）已上线。实际使用中暴露出一批回放体验与互动信息展示问题：

- 播放控件占据视频画面**下方**的独立区域，挤压画面空间，与主流视频站「控件悬浮于画面」的习惯不一致；
- 历史录播只能在线看，无法下载存档；
- 拖动进度条前无法预知目标位置的时间点；
- 全屏后再次点击全屏按钮**无法退出**（缺陷）；
- 缺少「网页全屏」（画面 + 弹幕列表充分利用浏览器窗口）的观看模式；
- 事件列表（弹幕列表）目前是把所有事件拍平成一行纯文本，丢失粉丝牌、礼物、SC 等全部结构化信息，可读性差。

本期目标：交付 6 项改进——**控件悬浮化、录播下载入口、进度条 hover 时间预览、全屏退出修复、网页全屏模式、弹幕列表信息流化**。

## 2. 用户场景

| # | 场景 | 描述 |
|---|------|------|
| S1 | 访客观看录播回放 | 控件悬浮在画面上，不遮挡时也易操作；静止不动鼠标时控件自动隐藏，画面最大化 |
| S2 | 访客想保存某场录播 | 在历史录播列表每行的按钮组中点「下载」，浏览器直接下载 FLV 文件 |
| S3 | 访客精确定位看点 | 鼠标在进度条上滑动时，跟随指针实时预览目标时间，再决定点击/拖动 |
| S4 | 访客进入/退出全屏 | 点击全屏按钮进入全屏，再次点击（或 Esc）正常退出，按钮状态与实际一致 |
| S5 | 访客专注看弹幕互动 | 进入网页全屏：左侧画面在剩余空间居中显示，右侧弹幕列表常驻，边聊边看 |
| S6 | 访客浏览弹幕列表 | 弹幕以信息流形式呈现：粉丝牌、浅色用户名、发言（含表情包）混排可换行；礼物、舰长、SC 各有醒目的卡片样式 |

## 3. 功能需求

### FR-1 播放控件悬浮于画面之上

- As a 访客，I want 播放控件悬浮在视频画面上，so that 画面不被挤压、观感与主流视频站一致。
- 回放页控件栏（播放/暂停、进度条、音量、倍速、弹幕开关、全屏等现有全部控件）从视频画面下方的独立区域，改为**覆盖在视频画面底部的悬浮层**。
- 悬浮层底部需有渐变/半透明背景保证按钮在亮色画面上可辨。
- 鼠标静止约 3 秒后控件自动隐藏（沿用现有自动隐藏逻辑），移动鼠标/触摸时重新出现；暂停时控件常显。
- 移动端：控件在悬浮层内仍可触达，不超出画面边界。

### FR-2 历史录播条目「播放/下载」按钮组

- As a 访客，I want 每场录播右侧有播放和下载入口，so that 可以在线看或下载存档。
- 历史录播列表每个文件项右侧增加按钮组：默认显示主按钮「**播放**」，右侧带下拉箭头；点击下拉箭头展开菜单，含「**下载**」项。
- 「播放」：跳转站内回放页（与点击条目本体一致）。
- 「下载」：浏览器直接下载录播 FLV 文件（录播服务同源直链，前端触发下载，不经本站中转）。
- 条目本体仍可点击进入回放页；按钮组不破坏现有布局，移动端可操作。
- 按钮图标使用 SVG/icon，不使用 emoji/Unicode 字形（沿用 R14-5 口径）。

### FR-3 进度条 hover 时间预览

- As a 访客，I want 鼠标在进度条上滑动时看到目标时间，so that 精确定位想看的位置。
- 鼠标指针在进度条上移动（未按下）时，在指针附近显示跟随的时间预览（如 `12:34`），格式与现有时间显示一致（`formatOffset`）。
- 预览时间随指针位置实时更新；指针离开进度条时隐藏。
- 与现有「按下拖动预览 + 松开提交 seek」逻辑并存，互不干扰。
- 移动端无 hover，不显示该预览（不影响现有拖动预览）。

### FR-4 修复全屏无法退出

- As a 访客，I want 全屏后再次点击全屏按钮能退出全屏，so that 不被卡在全屏状态。
- 全屏按钮为切换行为：非全屏时点击进入全屏；已全屏时点击退出全屏。
- Esc 等浏览器原生退出路径后，按钮图标/状态需恢复为「进入全屏」态（监听 `fullscreenchange` 同步状态）。

### FR-5 网页全屏模式（theater mode）

- As a 访客，I want 不切换操作系统全屏也能最大化观看区域，so that 同时看到画面和弹幕列表。
- 播放控件新增「网页全屏」按钮（与浏览器全屏按钮并存，图标可区分）。
- 进入网页全屏后：回放页舞台占满浏览器可视区域；**右侧为弹幕列表（事件列表），左侧为视频画面**；视频画面在其容器内**垂直水平居中**显示（而非顶部对齐），保持 16:9 比例、尽可能大地适配剩余空间。
- 播放控件仍悬浮于画面之上（FR-1 形态不变）。
- 再次点击网页全屏按钮（或明确的退出入口）恢复原页面布局。
- 网页全屏与浏览器全屏互斥：进入浏览器全屏时退出网页全屏态（或禁用网页全屏入口），退出浏览器全屏后回到进入前状态。
- 移动端屏幕过窄，不提供网页全屏入口（或入口禁用并说明），保持现有上下布局。

### FR-6 弹幕列表样式更新：信息流模式

- As a 访客，I want 弹幕列表按事件类型呈现结构化样式，so that 快速区分聊天、礼物、舰长与 SC。
- 事件列表整体从「单行纯文本」改为**信息流模式**，每条事件保留时间戳与点击跳转（seek）能力，自动跟随/回到底部等现有行为不变。
- **FR-6.1 弹幕（danmaku）**：inline 布局、支持换行，依次为「粉丝牌 badge（牌名+等级，牌子着色）」「用户名（浅色）」「冒号」「用户发言」；发言支持文字与表情包（`emote` 渲染为图片，图文混排）。
- **FR-6.2 礼物（gift / gift_v2）**：inline 布局、支持换行，展示发送者（沿用 6.1 的用户名/粉丝牌样式）+ 礼物信息（礼物图标、礼物名 ×数量、金额）。**API 调研结论（2026-09-25，见 §7）**：回放接口输出中 `gift_v2` 已由服务端归一化为 `gift` 类型，前端实际只会收到 `gift`；解析层防御性兼容 `gift_v2` 字面量即可，两者共用同一展示结构。
- **FR-6.3 舰长上舰（guard_buy）**：**独占一行**的醒目卡片，展示「用户名 + 开通了舰长/提督/总督（guard.name）×数量」及金额（如有）；视觉上与普通弹幕明显区分（如底色/边框）。
- **FR-6.4 醒目留言 SC（super_chat）**：**独占一行**的醒目卡片，展示用户名、SC 留言内容、金额；卡片配色使用接口返回的 `scColors`（背景渐变 + 文字色），缺失时使用默认醒目配色。
- 用户名颜色「浅色」指相对正文更弱的强调色，需保证在深色背景下的对比度可读。

|---|----------|----------|
| AC-1 | FR-1 | 回放页控件覆盖在视频画面底部（浮层），不再占据画面下方的独立布局空间；静止约 3s 自动隐藏、移动复现；控件全部功能（播放/进度/音量/倍速/弹幕开关/全屏）在浮层形态下可用 |

## 5. 非功能需求

- **响应式**：沿用 Mantine 断点（移动端 `< 48em`）；控件浮层、按钮组、网页全屏均适配移动端（网页全屏入口移动端不开放）。
- **性能**：事件列表信息流化后仍按窗口化数据渲染（沿用现有 10 分钟窗口增量加载），不得全量渲染长录播事件；礼物图标/表情图片需懒加载避免滚动卡顿。
- **可访问性**：全屏/网页全屏按钮有明确的 `aria-label` 与状态（`aria-pressed`）；新增交互可键盘操作；卡片配色不以颜色为唯一信息通道（保留文字类型标识）。
- **兼容性**：不改变 FLV/MSE 播放链路；iOS 降级提示行为不变。

## 6. 范围边界（本期不做）

- 弹幕发送、登录、评论等写操作。
- 礼物/SC 的浮层（横穿画面）动效——结构化事件仅出现在事件列表；视频浮层弹幕仍仅渲染 `danmaku` 类型（现状不变）。
- 录播转码、压缩、分段合并下载。
- 网页全屏下的自定义布局（如弹幕列表宽度调节、位置切换）。
- 事件列表的虚拟滚动库引入（沿用窗口化渲染，实测卡顿再议）。

## 7. 外部依赖与已验证项（API 调研，2026-09-25）

调研方式：实测 `https://api.sumire.live/api/live-events/replay`（当前在播房间 1727074031，8112 条事件全量扫描）+ 服务端归一化层源码（sumire `servers/api/src/liveEvents/normalize.ts`、`routes/liveEvents.ts`）。

| 项 | 结论 | 状态 |
|----|------|------|
| 输出事件类型 | 回放接口契约输出仅四类：`danmaku` / `super_chat` / `gift` / `guard_buy`；`type=` 查询参数可重复过滤 | 已验证 |
| **gift_v2** | 上游 B 站信封类型 `gift_v2`（`senderUinfo` + `giftList` 结构）在服务端归一化时**并入 `gift` 输出**（`toUpstreamTypes`：查 gift 即查 gift+gift_v2，前端透明）。前端**不会**收到 `type: "gift_v2"`；防御性兼容即可 | 已验证（源码 + 实测无 gift_v2 输出） |
| gift 结构 | `{ price, gift: { name, count, iconUrl } }`，`sender` 含 medal/guardLevel；实测样本：`{"price":0.1,"gift":{"name":"人气票","count":1,"iconUrl":"…"}}` | 已验证（实测） |
| guard_buy 结构 | `{ price?, guard: { level, name, count } }`；**上游事实：GUARD_BUY 无头像、无粉丝牌**（`face: null`、`medal: null`），`guard.level` 3=舰长/2=提督/1=总督；金额为 `price/1000` 元（服务端已折算） | 已验证（源码；近 7 天四房间实测无样本，属正常低频事件） |
| super_chat 结构 | `{ content?, price?, scColors?: { backgroundStart, backgroundEnd, fontColor }, time? }`；实测样本含 `scColors` 与 `time`（悬停秒数）——**当前前端类型定义缺失这两个字段，需扩展** | 已验证（实测） |
| 弹幕表情 | `emote: { url, name, width, height }`，图文混排渲染依据 | 已验证（实测） |
| 录播文件下载 | `GET {REC_BASE}/api/b/live/{roomId}/recordings/{file}` 为 FLV 字节流直链，可直接作为下载地址 | 已验证（回放链路同源） |
