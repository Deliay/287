# 页面优化一期 — 产品需求文档（PRD）

- 版本：v1.0
- 日期：2026-09-25
- 状态：待 Review

## 1. 背景与目标

站点一期上线后，在实际使用中暴露出四类体验问题：

1. 开播时，首页 Hero 立绘墙与成员详情区中的直播状态徽章点击后跳转的是 B 站**个人主页**，而非**直播间**，用户需要二次跳转才能看直播，路径冗余。
2. 首页整屏滚动的吸附（回弹到某个 liver 页面并占满全屏）没有动效、过于生硬，与站点整体的阻尼滚动手感不一致。
3. 录播页多个成员分组可同时展开，页面冗长；且展开状态只存在于内存中，刷新或分享链接后丢失，无法直达某个成员的录播列表。
4. 成员未开播时，首页详情区只展示不可点击的「未开播」文本，没有给出任何可操作的下一步，流量无法导向录播内容。

本期目标：缩短「看直播」路径、补齐滚动吸附动效、让录播页展开状态可分享可直达、为未开播成员提供录播入口。

## 2. 用户场景

- **场景 A（看直播）**：访客打开首页，看到某成员徽章显示「正在直播：{标题}」，点击徽章，期望直接进入该成员的 B 站直播间。
- **场景 B（浏览首页）**：访客在 PC 端用滚轮滑动首页，滚动停止在接近某个成员介绍区时，页面以**连续可见的动画**吸附到该区正中，而不是瞬间跳变。
- **场景 C（找录播）**：访客进入录播页，点击某成员分组展开录播列表；复制当前 URL 发给朋友，朋友打开链接后**自动展开同一成员**的录播分组；任何时候页面上**至多只有一个**成员分组处于展开状态。
- **场景 D（成员未开播）**：访客在首页浏览到某成员详情区，该成员未开播，详情区展示「未开播，看录播 ->」入口，点击后进入录播页并展开该成员的录播分组。

## 3. 功能需求

### FR-1 直播徽章跳转直播间

As a 访客，I want 开播状态下点击直播徽章直接进入直播间，so that 不必经过个人主页二次跳转。

- 首页 Hero 立绘墙（`HeroWall`）与成员详情区（`MemberSection`）中的直播状态徽章（`LiveBadge`），在**开播状态**下点击后新标签页打开 `https://live.bilibili.com/{roomId}`。
- roomId 取成员静态数据（`members.ts` 的 `roomId` 字段），四位成员的 roomId 已于 2026-09-25 通过线上录播服务接口实测确认（对照表见技术方案 §4）。
- 加载中与未开播状态行为不变（加载中为占位骨架、不可点击；未开播为纯文本）。
- 当 roomId 缺失时，降级为现有行为（跳转 B 站个人主页），不得渲染无效链接。

### FR-2 滚动吸附动效完整呈现

As a 访客，I want 首页整屏吸附带有平滑动画，so that 浏览体验连贯不生硬。

- PC 端（lenis 阻尼滚动）滚轮滑动停止并触发吸附时，吸附过程以连续动画完成，不得瞬时跳变。
- 移动端（CSS scroll-snap）吸附行为保持平滑，不出现硬性跳动。
- 若代码中存在针对 `prefers-reduced-motion` 等「减少动效」的降级 CSS/逻辑导致动效被裁减，应移除或无视该降级，以呈现完整动效为准（经排查当前仓库暂无此类规则，实现时需再次确认并防止引入）。

### FR-3 录播页单分组展开 + Query Param 同步

As a 访客，I want 录播页同一时间只展开一个成员分组且展开状态体现在 URL 中，so that 页面简洁、链接可分享、刷新不丢失状态。

- 录播页（`/recordings`）任一时刻**至多一个**成员分组处于展开状态；展开新分组时自动收起已展开的分组。
- 展开分组时，URL query param 中记录当前展开的成员标识（如 `?member={memberId}`）；收起时移除该参数。
- 带该参数访问（刷新、直接输入、他人分享）时，页面加载后自动展开对应成员的录播分组并加载其录播列表。
- 参数中的成员标识无效（不存在该成员）时忽略该参数，页面按默认（全部收起）渲染，不得报错。
- 更新 URL 不得触发页面刷新或滚动位置丢失（history 层面的替换）。

### FR-4 未开播时的录播入口

As a 访客，I want 成员未开播时在其详情区看到录播入口，so that 可以转向观看该成员的录播。

- 首页成员详情区（`MemberSection`）中，当该成员**未开播**时，展示入口链接文案「未开播，看录播 ->」。
- 点击后跳转至录播页并按 FR-3 的 query param 约定展开该成员的录播分组（即 `/recordings?member={memberId}`）。
- 开播状态下不展示该入口；直播状态加载中不展示（避免状态闪烁）。

## 5. 非功能需求

- **兼容性**：站点为静态导出（Cloudflare），所有改动须兼容静态部署，不引入服务端能力；query param 读写仅在客户端进行。
- **性能**：不新增运行时依赖；直播状态请求沿用模块级缓存，新增入口不得引入额外请求。
- **可访问性**：新增链接需有可读文案/aria 语义；动效改动不得破坏键盘与锚点导航。

## 6. 范围边界

本期**不做**：

- 不修改直播状态接口与录播服务接口的协议（仅在客户端做防御性解析与降级）。
- 不调整录播页的分页、回放页、弹幕等既有功能。
- 不处理 `src/data/members.ts` 中 sumire 的 `liveStatusUrl` 疑似缺少成员段的数据问题（另立项跟进）。
- 不改动 Hero 立绘墙的页内锚点跳转行为（`#member-{id}`）。
- 不做全局的 `prefers-reduced-motion` 无障碍适配体系建设（本期仅按需求保证完整动效呈现）。
