# 产品需求文档（requirement）规范

本目录存放产品需求文档（PRD），是开发前置流程的**第一阶段**产出物。

## 何时编写

任何新功能、重大变更或重构需求，必须先在此目录建立需求文档，之后才能进入 UI/UX 阶段。

## 文档必须包含的内容

1. **背景与目标**：为什么做这个需求，解决什么问题。
2. **用户场景**：谁在什么情况下使用，核心使用路径。
3. **功能需求**：逐条列出，可使用用户故事（As a ... I want ... so that ...）。
4. **验收标准**：每个功能点对应的可验证的验收条件（这是后续编写测试的依据）。
5. **非功能需求**（如适用）：性能、兼容性、安全等约束。
6. **范围边界**：明确本期**不做**什么，避免范围蔓延。
7. **Review 记录**：评审人、评审日期、结论（通过 / 不通过及原因）。

## 完成条件（DoD）

- 需求描述与验收标准明确、无歧义。
- 通过 Review 并记录在文档中。
- 对应的 UI/UX 文档（`../design/` 同名主题）建立后，本阶段才算流转完成。

## 注意事项

- 需求变更时直接修改本文档并标注变更日期，同时通知下游（设计、技术方案）同步更新。
- 文档命名遵循 `../AGENTS.md` 中的通用约定，主题名与其他目录保持一致。
