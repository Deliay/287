# 技术方案文档（proposal）规范

本目录存放技术方案文档，是开发前置流程的**第四阶段**产出物（需求与设计通过 Review 之后）。

## 何时编写

对应主题的需求文档与设计文档均已通过 Review 后，才开始本阶段。

## 文档必须包含的内容

1. **对应上游文档**：引用 `../../product/requirement/` 与 `../../product/design/` 中的同名主题文档。
2. **技术选型**：使用的语言、框架、库及选型理由；如引入新依赖，必须说明必要性。
3. **架构设计**：模块划分、数据流、与现有代码的关系（引用具体文件路径）。
4. **接口设计**（如适用）：API、数据结构、状态管理的定义。
5. **风险与权衡**：主要技术风险、备选方案及取舍理由。
6. **测试策略**：计划覆盖的单元测试范围，如何满足需求文档中的验收标准。
7. **评审记录**：评审人、评审日期、结论（通过 / 不通过及原因）。

## 完成条件（DoD）

- 方案通过技术评审。
- 评审通过后，才能编写实现计划（`../plan/` 同名主题）。

## 注意事项

- 技术方案描述"做什么、为什么这么做"，具体任务拆解放到 `../plan/`。
- 方案变更时同步更新本文档，并通知下游实现计划同步调整。
- 文档命名遵循 `../AGENTS.md` 中的通用约定，主题名与需求、设计文档保持一致。
